# Issue reports and support

Questions, corrections, compatibility reports, and architecture reviews are welcome through [GitHub issues](https://github.com/ghosty-11/hermes-stackbook/issues).

## Before opening an issue

1. Search existing issues.
2. Read the relevant guide section and its primary sources.
3. Check the installed Hermes and OMP versions and current CLI `--help`.
4. Remove credentials, private identifiers, production paths, and third-party personal data.

## Useful reports

A useful issue includes:

- the guide page and statement in question;
- the observed behavior, not only the expected behavior;
- Hermes, OMP, OS, provider, and model versions that materially affect it;
- a minimal reproduction or bounded command output;
- current official documentation or source when proposing a correction;
- what remains uncertain.

Use fictional repository keys and `example.invalid` for non-resolving domains. Do not attach unbounded logs, private topology, credential files, provider tokens, bot/account IDs, or copied proprietary plugin/skill bodies.

## Maintainer response

Issues are reviewed as time permits. The maintainer may answer questions, help narrow a failure, update the guide, or close reports that cannot be reproduced or fall outside the project's scope. There is no support SLA.

## Repository boundary

This repository owns architecture, decisions, procedures, contracts, and verification guidance. It is not an installer or a mirror of upstream documentation. Exact deployment manifests depend on the operator's OS, network, providers, and risk policy.

AI assistants preparing issue evidence should follow [AGENTS.md](AGENTS.md).
